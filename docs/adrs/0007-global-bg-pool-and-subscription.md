# 7. 全局 bg 池与订阅模型：脱离任务从独占属主到多会话订阅

Date: 2026-10-08

## Status

Accepted

## Context

0006 + #19 的现状：脱离任务清单记录 `ownerPid`，属主存活的池对本进程不可见、不可领养、不清理；属主死亡后由下个会话以 rm+`wx` 独占认领。单机单会话主线自洽，但三个真实场景卡住：

1. **并发会话**：同一台机器多个 pi 进程（Orca worktree、多终端并行）互相看不见对方的脱离任务——想接手只能等属主退出或杀掉对方。
2. **归属粒度**：`ownerPid` 是进程级标识，pi 一退出即失效；`pi -c`/`--resume` 复活同一对话时，新进程在进程层面是「陌生人」（早前 DOA 唤醒草案已指出此误伤）。
3. **认领=抢走**：独占转移语义自带 claim → 旧主察觉 → 弃管的状态机与 split-brain 窗口。

技术前提变化：`PI_SESSION_ID` 环境变量对扩展进程可用（pi 官方 environment-variables.md 文档化）——早前 DOA 唤醒草案（2026-10-02，未编号未合入，内容并入本 ADR）当年「扩展面无稳定会话标识」的拒绝理由已过期。

维护者裁决（2026-10-08 讨论锁定）：任务直接入机器级全局池；认领 = 增加一个汇报对象而非转移所有权；会话 bg 池只装自己的与已订阅的。三个决策点：①杀权归创建者或任一订阅者，唤醒注明凶手；②自动重订阅仅限同 sessionId；③多订阅者唤醒倍增是特性。

## Decision

1. **全局池**：`pi-bg-shell/` 根目录升级为机器级任务板。清单从「属主凭据」变「公告板」：spawn 时记录 `sessionId`（取 `PI_SESSION_ID`；`pi -p --no-session` 等无会话运行留空，此类任务永不自动重订阅）与 `creatorPid`（杀权血缘），移除 `ownerPid` 独占语义。目录结构（每注册表实例一个 mkdtemp 会话子目录）与 0600/0700 权限模型不变。
2. **订阅协议**：每个订阅者一个 `<token>.sub.<pid>` 标记文件——`wx` 独占创建（EEXIST = 已订阅）、0600、与 `.fired` 标记同款 CodeQL 安全模式。订阅单调、可交换、无锁；退订 = unlink 自己的标记。session 注册表（bg_status / 面板 / 唤醒管线的视图）只装自己的 + 已订阅的任务。
3. **死亡讯息是池级职责，不依赖订阅**：扫描器发现终态且无 `<token>.reported` 标记 → 合并补发（100ms debounce 一条 grouped 消息、`unattended` 陈旧标注 + 状态文件 mtime 近似时长——设计继承自早前 DOA 草案）→ 打标记。任何会话开局都「知道发生过什么」，无论认不认领。
4. **自动重订阅仅同 sessionId**：开局扫描，manifest `sessionId` == 本进程 `PI_SESSION_ID` → 自动订阅（语义等价 0006 的「自动领养」，但按对话身份匹配而非机器位置）。异 id 任务列入 bg_status 全局池 foreign 分区：可见、不唤醒、无杀权；显式 `bg_adopt {id}` 订阅（wx 标记 + 注册表入列 + on_pattern 续效 + 沿用 0006 的陈旧命中补发规则）。
5. **杀权与通知**：创建者或任一订阅者可 `bg_kill`；kill 事件唤醒所有订阅者并注明发起会话。
6. **生命周期**：dispose 从「删文件」降级为「退订」（只动自己的标记）；文件回收归扫描器——终态 + 无活订阅标记 + 已 reported → 收集。非 detached 任务不进池（会话内存态子进程，物理边界，写死）。
7. **跟踪去中心化**：每个订阅者独立轮询状态/输出文件、独立 LineMatcher、独立唤醒——文件本就是事实源，N 个读者零冲突，2s 轮询的 syscall 开销可忽略。

## Considered Options

- **维持 0006/#19 独占属主**——并发会话不可见不可接手，真实场景已出现；被本 ADR 修订。
- **所有权转移式认领（rm+wx 改写属主 + 旧主下个轮询察觉弃管）**——可行，但 claim→察觉→弃管状态机自带 ≤2s split-brain 窗口；订阅模型用可交换标记把整个状态机消解为不存在。
- **observe-only（可见可观察、不动所有权、各自唤醒）**——杀权归属与双醒语义糊（bug 还是特性说不清）；订阅模型把「持续被唤醒」与「可见」显式分层。
- **同 cwd 自动订阅**——维护者否决：承诺主体是 session 不是目录；且全局池可见性已解决新会话发现任务的问题（0006 当初被迫选自动领养的鸡生蛋前提不复存在），异会话手动认领的成本只剩一步有信息的仪式。
- **清单内嵌订阅者列表**——多进程并发改写同一 JSON 需要锁协议；wx 标记文件免锁达成同等语义。
- **DOA 唤醒先按属主模型单独落地再叠加本 ADR**——早前草案的路径；只动 DOA 分支但按属主模型实现，本 ADR 落地时需重写为 `.reported` 标记路径，属 double work；并入（debounce 合并、unattended 标注、失约成本论证原样继承）。

## Consequences

- 正面：并发会话协作（可见 + 自愿订阅 + 无抢走惊讶）；死亡讯息不依赖任何会话存活；resume 接续按对话身份精确匹配；领养竞态、双份跟踪、属主察觉延迟一类问题从结构上消失（没有所有权转移就没有转移竞态）。
- 负面/接受：N 个订阅者 = 每事件唤醒 ×N（特性，知情接受）；每订阅者一个轮询器（开销可忽略）；同 uid 同信任域前提不变（恶意会话可订阅/杀任务，与 0006 同威胁模型）；`PI_SESSION_ID` 依赖上游稳定性（已文档化的公开变量，风险低）；升级前旧清单无 `sessionId` 字段 → 按「可见 + 手动认领」处理，不自动。
- 修订关系：修订 0006 Decision 第 4 条（领养条款）；早前 DOA 唤醒草案（2026-10-02，未编号未合入）被本 ADR 取代，其 debounce 合并与 `unattended` 标注设计并入第 3 条。
- 实现面：adoptDetached 扫描重写、`bg_adopt` 工具、bg_status foreign 分区、CONTEXT 词条（全局池/订阅/认领）、双 README、测试面（订阅原子性、异会话可见性、死亡汇报幂等、同 id 自动重订阅、退订后回收）。
